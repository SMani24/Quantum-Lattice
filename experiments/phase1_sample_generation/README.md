# Solvable-model sample generation

This is the first part of Phase 1. It generates a small, Hamiltonian-grouped
dataset for later MLP/CNN comparisons; it does not train a network. The default
is 16 independent L=4 Hamiltonians with signed Z fields drawn uniformly from
[-0.2,0.2]. This weak-field pilot is our choice, not the paper's full training
domain or a topological-phase certification.

## Start with a short benchmark

From the repository root, using the existing environment:

```sh
source .venv/bin/activate
python -m pip install -r requirements-phase1.txt
python -m pip install --no-build-isolation --no-deps -e .
python experiments/phase1_sample_generation/run.py benchmark --workers 4
```

The benchmark uses four Hamiltonians and 5,000 sweeps each, saves its effective
overrides separately, and estimates the configured pilot's time on your machine.
It checks throughput, not adequate equilibration. The first process startup
loads/warms the compiled kernel. `--workers 1` gives a useful serial comparison.
Without Numba, `backend: auto` falls back to the slower Python reference.

Running the script with no arguments opens a short menu. To start the configured
pilot after discussing its settings:

```sh
python experiments/phase1_sample_generation/run.py run --config configs/phase1_sample_generation.json --workers 4
```

No full dataset is generated by installation or tests. Use `--help` on the runner
or any subcommand for its options; `--plain` disables interactive keys.

## Pause and continue

The progress panel shows attempts, retained samples, completed Hamiltonians,
elapsed time and an approximate ETA. Press **p** to pause, **r** to continue,
or **q** / **Ctrl+C** to save and exit. Active bounded chunks finish before the
display confirms that checkpoints are saved. With the default `chunk_sweeps:
1000`, responsiveness depends on how fast your machine runs those sweeps.

The printed run directory is your resume handle. Keep it, then use:

```sh
python experiments/phase1_sample_generation/run.py resume --run-dir "codex material/artifacts/phase1_sample_generation/runs/YOUR-RUN" --workers 4
```

You may change the worker count when resuming. Saved scientific settings, random
states, NumPy version and relevant source fingerprints are checked; changing them
is rejected. Keep the recorded NumPy version for exact RNG continuation.
An unrelated Phase 0 plotting or future neural-network edit does not block resume.
No other process can own the same run simultaneously. Checkpoints are atomic;
an abrupt interruption can lose the current chunk, then resume from the last
saved checkpoint without changing the eventual samples. Save/quit before closing
the shell. Pause boundaries do not restart burn-in or uncertainty blocks.

## What one chain generates

We start with all edge spins +1, preserving plaquettes and the reference Wilson
sector. One sweep is V=L² attempted slots with uniformly selected vertices,
with replacement. Each nonlazy proposal flips one whole star immediately if
accepted with `min(1, exp(-2*sum_incident(b_e*s_e)))`.

With 100,000 total sweeps, 10,000 burn-in sweeps and a stride of 20, records are
taken after sweeps 10,020, 10,040, ..., 100,000: **4,500 records per Hamiltonian**.
Unlike the supplied zero-based attempt loop, this is clean sweep-boundary timing.
We also add a 5% self-loop probability to prevent zero-field periodicity; setting
it to zero restores the authors' proposal rule. Rejections and self-loops remain
in the record schedule, including repeated configurations.

Every record provides all V star estimators, E neighboring-star pair estimators,
and E single-Z values. Star estimators are `exp(-sum_star(b_e*s_e))`; the pair
uses the symmetric difference of the two star supports, cancelling shared edges.
These known-field estimators may exceed one; they are not finite-shot X-basis
measurement outcomes. We do not clip them.

Each L=4 Hamiltonian gives 16 star means, 32 neighboring-pair means, 32 Z means,
and **32 local MLP rows** `(A_u,A_v,A_u*A_v expectation)` with target `abs(b_e)`.
The third entry is the two-star expectation, not the product of star means.
The default bank has 512 local rows, grouped into 12 training / 2 validation /
2 test Hamiltonians (384 / 64 / 64 rows). This is a pipeline pilot, not a
sufficiently established training dataset. All rows from a Hamiltonian stay in
one split; more correlated local rows do not create new independent instances.
Balanced split blocks preserve existing assignments when the bank size grows
at fixed seed and fractions. `hamiltonian_uid` identifies repeated Hamiltonians
across runs. If you later combine banks, deduplicate or regroup by that UID;
benchmark data are speed checks and should not be added to the learning bank.

Ordinary means use every retained record. Complete blocks of 45 records give
batch-means standard errors (100 blocks at the defaults). Naive IID errors are
stored for comparison. A partial final block contributes to the mean but not
the block SE; missing SEs are NaN. Scalar autocorrelation/ESS diagnostics follow
an initial monotone lag-pair estimate, conservatively flooring tau at one;
they do not establish equilibration or agreement across independent chains.
See the [Stan reference discussion of lag-pair truncation](https://mc-stan.org/docs/reference-manual/analysis.html).

## Code and saved files

| Path | Responsibility |
|---|---|
| `src/quantum_lattice/lattice/` | Immutable topology and square construction |
| `src/quantum_lattice/simulation/solvable.py` | Sequential chain, optional Numba kernel, RNG/checkpoints |
| `src/quantum_lattice/observables/solvable.py` | Shared-sample estimators and exact tiny-orbit enumeration |
| `src/quantum_lattice/observables/statistics.py` | Means, block SEs, scalar autocorrelation diagnostics |
| `src/quantum_lattice/data/generation.py` | Seed/group plan, worker scheduling, atomic storage and verification |
| `src/quantum_lattice/simulation/terminal.py` | Terminal controls and progress display |
| `configs/phase1_sample_generation.json` | Pilot settings |
| `experiments/phase1_sample_generation/run.py` | Thin CLI/menu runner |

`results/` is a local shortcut to ignored
`codex material/artifacts/phase1_sample_generation/`. Each `runs/<run-id>/` holds:

| File | Contents |
|---|---|
| `config.json`, `manifest.json` | Effective settings, seeds/splits, environment, source hashes and conventions |
| `checkpoints/<id>.npz` | Partial records, current spins, counters, full RNG state; removed after completion |
| `instances/<id>.npz` | One completed Hamiltonian and all aligned arrays |
| `instances/<id>.json` | Human-readable counts, acceptance, timing and scalar diagnostics |
| `dataset.json` | Completed instance paths/checksums and grouped split counts |
| `status.json`, `last_session.json` | Run state and latest session timing |
| `verification.json` | Storage/seed/estimator/plaquette/Wilson checks; not a mixing certificate |
| `benchmark.json` | Short benchmark settings, timing and same-host extrapolation, when applicable |

NPZ arrays include `states` (records,E), `b_z` (E,), `edge_vertex_indices` (E,2),
`star_values` (records,V), `pair_values` and `z_values` (records,E), each channel's
`*_mean`, `*_iid_se`, `*_block_se`, `*_block_means`, `mlp_X` (E,3), `target_abs_b`
and `target_b` (E,), plus JSON strings `metadata_json` and `summary_json`.
Load with `numpy.load(path, allow_pickle=False)`.

Square indices use vertex `y*L+x`, edge `2*(y*L+x)+orientation`, outgoing horizontal
orientation0 and outgoing vertical1. Supplied author flattened field files use
a different coordinate/orientation convention; importing them requires an
explicit mapping. No supplied files are modified by this runner.

CPU multiprocessing is over independent Hamiltonians. Moves within a chain
remain sequential. Each process uses one BLAS thread; a GPU is not needed for
this small pilot. Storage is per instance so later datasets need not fit in RAM.

Inspect or verify a run with the `status` and `verify` subcommands. Meaningful
tests cover exact L3 wavefunction expectations, detailed balance, sector
invariants, Python/Numba parity, grouped splits and exact interrupted/resumed
datasets with different worker counts and chunk sizes.
